// PROCESS

How I Approach Testing

A structured approach that takes a feature from requirement review through testing, defect resolution, and release validation.

01

Understand Requirements

I start by understanding the requirement, acceptance criteria, and expected user behavior. I clarify anything unclear early and identify important edge cases before testing begins.

02

Plan the Coverage

I break the requirement into test scenarios and consider the business impact, affected areas, and possible regression risks.

03

Design Test Cases

I create clear test cases with expected results and relevant test data, making sure the important requirements are covered and traceable.

04

Execute & Automate

I execute the planned tests and explore areas where the actual behavior may differ from the expected result. For repetitive or suitable regression scenarios, I use Selenium WebDriver with Java and TestNG to support automation.

05

Investigate & Report Defects

When I find an issue, I reproduce it, collect the required evidence, document the impact clearly, and work with the development team to get it resolved.

06

Retest & Validate the Release

I verify fixes, run the required regression checks, and support release validation to make sure the change works as expected without affecting existing functionality.
